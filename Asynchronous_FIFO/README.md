# Asynchronous FIFO

## Description

This project implements a parameterized Asynchronous FIFO (First-In First-Out) memory using Verilog HDL.

The FIFO operates with independent write and read clocks, allowing write and read operations to occur in separate clock domains. The design supports configurable data width and address width through Verilog parameters.

The project was designed and simulated using Xilinx Vivado.

## Features

- Independent write and read clock signals
- Parameterized data width
- Parameterized address width
- Configurable FIFO depth
- Separate read and write pointers
- Full and Empty flag generation
- Independent read and write operations
- Verilog HDL implementation

## Parameters

| Parameter | Default Value | Description |
|-----------|---------------|-------------|
| `DATA_WIDTH` | 8 | Width of each FIFO data word |
| `ADDS_WIDTH` | 4 | Address width of the FIFO |

The FIFO depth is calculated as:

`DEPTH = 2^ADDS_WIDTH`

With the default `ADDS_WIDTH = 4`, the FIFO contains 16 memory locations.

## Inputs and Outputs

### Inputs

| Signal | Description |
|--------|-------------|
| `wr_clk` | Write clock |
| `rd_clk` | Read clock |
| `rst` | Reset signal |
| `wr_en` | Write enable |
| `rd_en` | Read enable |
| `data_in` | Input data to be written into FIFO |

### Outputs

| Signal | Description |
|--------|-------------|
| `data_out` | Data read from FIFO |
| `full` | Indicates that the FIFO is full |
| `empty` | Indicates that the FIFO is empty |

## Working Principle

The FIFO uses separate write and read clocks.

During a positive edge of `wr_clk`, when `wr_en` is asserted and the FIFO is not full, the input data is stored in the FIFO memory and the write pointer is incremented.

During a positive edge of `rd_clk`, when `rd_en` is asserted and the FIFO is not empty, data is read from the FIFO memory and the read pointer is incremented.

The lower bits of the read and write pointers are used to address the FIFO memory locations.

An additional pointer bit is used to help distinguish between the Full and Empty conditions when the address portions of the pointers are equal.

## Empty Condition

The FIFO is considered empty when the write pointer and read pointer are equal.

## Full Condition

The Full flag is generated by comparing the read and write pointers. The additional pointer bit is used along with the address bits to determine when the FIFO has reached its maximum storage capacity.

## Future Improvement

For a production-level asynchronous FIFO, clock-domain crossing techniques such as Gray-code pointer conversion and multi-stage synchronizers can be incorporated to safely transfer pointer information between the write and read clock domains and reduce metastability risks.
